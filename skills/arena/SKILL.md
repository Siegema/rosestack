# Arena

Use when one attempt would prematurely lock in a costly choice. Do not use it
for routine edits. The requested artifact determines authority: a design arena
does not authorize implementation. Obey host permissions and the primary's launch
budget; never route around denied delegation or spawn nested children.

## Frame

State the user outcome, artifact, exact scope/base, constraints, evidence, and
three to six gradeable criteria. Separate hard gates from preferences. Give all
candidates the same task and constraints. Decide the rubric before seeing output.
Default to two candidates; each gets disjoint files or an isolated worktree.
Reserve final review and possible follow-up capacity before spending launches.

## Compare

Candidates produce an artifact plus alternatives considered and rejected. They
do not inspect one another's in-progress work, publish, or launch children. The
primary reads every completed candidate, applies hard gates, and scores each
criterion with concrete evidence. Candidate agreement is not a correctness proof.

Use a fresh judge only if budget permits. Identify its independence and model
family honestly. Same-model separate contexts are useful but not model diversity.
If delegation is unavailable, offer a clearly labeled single-agent comparison;
do not claim a completed independent arena. Report failed or missing candidates.

## Synthesize and verify

Choose one coherent base. Port only specific improvements that fit its model,
recording their source and rationale. Do not average incompatible designs. If
candidates diverge because requirements were unclear, report the ambiguity rather
than consuming unbounded retries. The primary owns integration and reruns checks.

Output the rubric, candidate comparison, selected base, judge status, accepted
improvements, rejected ideas, convergence/dropouts, checks, and gaps. An implemented
artifact still needs actual behavior verification and fresh final review; judging
early candidates is not a review of the integrated patch.
